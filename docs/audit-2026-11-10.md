# Repository audit, 10 November 2026

## Scope

The starting checkout contained 1,580 tracked files and 129 package manifests.
The audit inventoried the repository, checked workspace dependencies and local
documentation links, and reviewed the architecture and critical execution paths.
Manual review concentrated on plugin composition and lifetime, transport,
session and agent persistence, tools, configuration, installation, and web input.
This is a prioritized findings list, not a claim that every source line has been
reviewed or that every possible defect has been found.

## Fixed

Each reproduced failure below has regression coverage. The dictionary fixes also
cover equivalent accumulators in trace attributes, session cache reports,
codemode storage, and file icon rules.

| Area                | Failure and resulting behavior                                                                                                                                                                                                                                                                       |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Agent state         | A missing session named `../auth` caused cleanup to delete JSON files outside the agent directory. Session ids are now escaped into individual filenames. An id ending in `.live` also keeps its journal separate from another session's live output.                                                |
| Input decisions     | Once 1,024 newer answers filled the cache, an unfinished decision could be evicted and its hook invoked twice for the same request. Pending decisions now stay shared until they settle.                                                                                                             |
| Client cancellation | Aborting a repeatable call during reconnect left its promise waiting for a connection. Reconnect waits now observe cancellation and release their listeners.                                                                                                                                         |
| HTTP serialization  | A complete NDJSON line bypassed the 16 MiB limit when its newline arrived in the same chunk. Completed lines are now checked before parsing; a large chunk containing several valid lines still works.                                                                                               |
| Plugin composition  | Plugin ids such as `__proto__`, `constructor`, and `toString` could disappear, inherit config or scope values, or evade replacement. Dictionary writes and optional lookups now preserve own keys across the kernel, host, planner, and catalog. Required service aliases also preserve these names. |
| Config parsing      | The JSONC parser dropped `__proto__` entries. Reading the parser's tree preserves those entries, and cloning the result preserves ordinary JSON objects so an unchanged config reload does not restart plugins.                                                                                      |
| CLI and forms       | Undeclared options could be accepted through inherited properties. Arguments and form fields could disappear or satisfy required checks without a value. Boolean parsing accepted `__proto__`. These paths now require their own entries and keep arbitrary declared names.                          |
| MCP                 | Servers, tool exposure overrides, and saved sign-ins named `__proto__` were lost on write. These records now persist and reload correctly.                                                                                                                                                           |
| Router              | Path and search parameters could lose object property names or inherit missing values. A rejected memory-history push also advanced the current index. Parameters now preserve their keys, and a failed push preserves the entry and forward history.                                                |
| Markdown            | Model HTML could fetch audio, video posters, tracks, and table backgrounds despite the sanitizer's stated no-fetch policy. Media elements and resource-loading attributes are now removed. Ordinary links keep their existing external-link behavior.                                                |
| Other dictionaries  | Frontmatter fields and keyboard overrides lost `__proto__`; absent overrides could inherit object properties. These records now preserve declared keys and use defaults for absent entries.                                                                                                          |
| npm launcher        | A failed extraction or runtime probe called `process.exit` inside a `try`, bypassing staging cleanup. Failures now unwind through `finally` before the launcher reports them.                                                                                                                        |

The default session store generates ids that keep their existing filenames.
Escaped ids use a separate directory so their filenames cannot overlap legacy
literal ids. Legacy journals retain their original ids and migrate on write.

## Review next

The following findings come from code inspection. Their concurrency and failure
scenarios need focused reproductions before choosing an implementation.

### 1. Admit tool and guard execution through the registry lifetime

[Tool execution](../domains/tools/registry/src/registry.ts) reads contributions
with `registries.items`, then directly invokes tools and guards.
[Registries.run](../packages/core/src/registries.ts) provides admission and makes
contributor disposal wait for admitted work before running finalizers.
Direct invocation bypasses that guarantee and the context used to defer a
plugin's request to reload itself.

Review how an executing tool should behave when its plugin reloads: finish,
cancel, or return a result the agent can safely replay. Reproduce with a tool
held on a gate, remove its plugin, and assert when its finalizers run.

### 2. Coordinate profile deletion with host startup

[removeProfile](../domains/profiles/contract/src/local.ts) checks discovery and
then recursively removes the home. [Host startup](../packages/host/src/process.ts)
holds `host.lock` before the transport publishes discovery. Discovery alone
therefore leaves a startup window, as well as a gap between checking and deleting.

Use a deletion protocol shared with host startup. Reproduce by pausing startup
after acquiring its lock and attempting profile deletion before discovery exists.

### 3. Keep a deferred rollback from overwriting a newer config

[Deferred configuration](../packages/host/src/control.ts) writes a file and may
apply it after the requesting work ends. On failure it runs the captured
[ConfigUpdate.restore](../packages/host/src/config.ts), which restores the old
text without checking whether the file has since changed. The deferred failure
handler performs that restore outside the reload semaphore.

Decide whether rollback should require the current file to match the text that
operation wrote, or whether all deferred writes and rollbacks should be ordered
together. A regression should interleave two writes and fail the older apply.

### 4. Bound output queues all the way to the consumer

[OutputAccumulator](../domains/tools/bash/src/output.ts) bounds its retained
head and tail but ignores the return value of `WriteStream.write`. A slow disk
can therefore retain a growing queue of raw output. The
[tool registry](../domains/tools/registry/src/registry.ts) also uses an unbounded
outbox when a listener consumes output more slowly than a tool produces it.

Measure memory with a fast producer and a deliberately slow sink. Choose where
to pause the producer or spool output. Preserve the client rule that a slow
stream consumer must not block every RPC on the shared connection.

### 5. Coordinate worktree removal with new work

[workspace.tidy](../domains/workspace/tidy/src/index.ts) snapshots open sessions
and running turns before calling `removeWorktree`. Its own tidy and restore jobs
are serialized, but a new prompt or unarchive can arrive after the snapshot.

Reproduce with removal gated after the snapshot, then start a turn in that
worktree. Review whether the workspace needs a reservation that turn startup
and removal both honor. Ignored files already do not count as changes, as the
[plugin README](../domains/workspace/tidy/README.md) states; confirm that this
remains the desired deletion policy for local files such as `.env`.

### 6. Define codemode durability when journaling fails

[Codemode journals](../domains/tools/codemode/src/journal.ts) append without
syncing and silently stop recording after a write failure while execution
continues. If a tool runs after its start record was lost, a later restart lacks
the evidence used to avoid running it again. The
[documented resumption behavior](../domains/tools/codemode/README.md) should
state the disk-failure and power-loss limits.

Choose whether unsafe calls should fail closed when their journal cannot be
written, and whether the guarantee requires syncing. Test a failed start-record
write followed by a successful tool side effect and a restart.

### 7. Recover watchers when parent directories appear or return

[Config watchers](../packages/host/src/watch.ts) skip absent parent directories
until restart. Plugin watchers attach to the plugin directory's parent, which
also fails when the project's `.lemma` directory is absent. A watcher that loses
its directory on an error is closed without a retry.

Choose whether creating or replacing `.lemma` during a running host should be
supported. If so, watch the nearest existing ancestor and reattach after changes.
Cover creation and directory replacement on Linux and macOS.

### 8. Recover an installer lock with no published pid

[The shell installer](../scripts/install.sh) creates its lock directory before
publishing `pid`. A crash between those operations leaves an empty lock that
subsequent runs always treat as another active installation.

Choose a portable recovery rule that distinguishes an abandoned empty lock
from an installer still publishing its pid. Add an interruption test at that
boundary; avoid reclaiming a live installer's lock based only on an empty read.

### 9. Decide whether project trust follows symlinks

[isTrusted](../packages/host/src/config.ts) compares lexical absolute paths.
A symlink under a trusted root can lead outside it while retaining trust by its
spelled path. Review whether trust should follow the physical checkout or the
user-selected path. Changing that policy requires tests for symlinked projects
and an explanation in the configuration documentation.

### 10. Reject or represent dot-valued route parameters

[Path construction](../packages/router/src/path.ts) uses `encodeURIComponent`,
which leaves `.` and `..` unchanged. URL parsing normalizes those segments, so
a parameter with either value can navigate to another path. Review whether the
router should reject those values or provide another representation. Test the
round trip through `new URL`, rather than only comparing the constructed string.

## Efficiency and removal candidates

- The default [development shell](../flake.nix) includes editor tooling. A cold
  setup fetched substantial Nix dependencies before project tools could run.
  Consider an optional editor shell and measure cold setup time before changing
  the default developer experience.
- Several caches are keyed by paths or working directories. In particular,
  [skill discovery](../domains/skills/files/src/skills.ts) deserves a lifetime
  review for hosts used across many changing projects. Measure retained entries
  before adding eviction policy.
- Plugin manifests, dynamic loading, compatibility readers, examples, and
  conformance suites make reference-only dead-code searches insufficient.
  No package or compatibility reader was established as safe to remove.

## Verification

Regression tests were run against the broken behavior before the corresponding
fixes. The sanitizer regression also failed in Chromium before its fix.
The first broad run caught and helped repair an unintended config reload caused
by object prototypes changing during parsing.

The following commands passed locally:

- `nix develop -c pnpm check`.
- `nix develop -c pnpm test`: 292 files passed, 2,472 tests passed, 20 skipped.
- `nix develop .#browser -c pnpm --filter @lemma/web-app ui:check`.
- `nix develop .#browser -c pnpm package:check`.
- `nix develop .#browser -c pnpm browser:check`.
- `nix develop .#browser -c pnpm exec vitest run domains/browser/chromium`:
  all 31 tests passed, including the 20 skipped in the default shell.

External provider accounts, native desktop launch, and other operating systems
remain outside the local verification performed on this Linux host.
