# Bounded Herdr case study

## Scope

Herdr is pinned to
[`d76657f2c7fc18dcce3b9af43842c8afaba1646b`](https://github.com/herdrdev/herdr/tree/d76657f2c7fc18dcce3b9af43842c8afaba1646b).
Its vendored Ghostty was
[`c5a21edfcbc2d5b46540ad91b7980aca31f5f1f3`](https://github.com/herdrdev/herdr/blob/d76657f2c7fc18dcce3b9af43842c8afaba1646b/vendor/libghostty-vt.vendor.json).
This is a regression source, not an architecture to copy. “Target Ghostty” below means Lemma's
qualification commit `226a91658da6400140a7da3f38b825ba0395bd5d`.

The list is intentionally capped at 20. Revisit it only during a Ghostty upgrade or after a relevant
incident.

## Completion rule

Each applicable row names an executable disabled regression in
[`tests/ghostty_parity_regression_test.cpp`](../tests/ghostty_parity_regression_test.cpp), or is
covered by the same test as an inseparable variant. “API-level fix” never waives a Lemma test: it
means the target Ghostty provides the primitive and Lemma must stop duplicating it. The case-study
list is complete for M0 when all named tests have become enabled and passing or a row is amended with
a reviewed not-applicable reason.
