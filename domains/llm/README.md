# llm

Models and their providers: what the agent asks, and how a person connects one. Its contract is [`@lemma/llm`](contract/src/llm.ts), with the web app's side in `@lemma/llm/web`.

| Plugin                                     | Halves     | What it does                                                                                                                                                                             |
| ------------------------------------------ | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`llm.pi-ai`](pi-ai/README.md)             | host       | Provides `Llm` over pi-ai's providers, the user's own, and those plugins add; serves it as the `llm.*` channels                                                                          |
| [`llm.commands`](commands/README.md)       | host       | The model providers' commands: log out of one                                                                                                                                            |
| [`llm.small-model`](small-model/README.md) | host + web | The model small tasks run on, such as a thread's title: provides `SmallModel`, the model set in Settings › General › Text generation models, else a small model of the thread's provider |
| [`llm.client`](client/)                    | web        | Providers and models as the host reports them, and this browser's choices: provides `Models`                                                                                             |
| [`llm.model-picker`](model-picker/)        | web        | The model and reasoning pickers, which `mod+shift+m` and `mod+shift+e` open in the composer                                                                                              |
| [`llm.providers`](providers/)              | web        | Settings › Providers: connecting providers, and adding your own                                                                                                                          |
| [`llm.cli`](cli/README.md)                 | host       | The `lemma` command's `models`, `providers`, `login`, `logout`, and a check for `lemma doctor`                                                                                           |

A plugin replacing `llm.pi-ai` runs `llmConformance` from `@lemma/llm/testing`: the tests `llm.pi-ai` passes, against the contract alone. The same module's `scriptedLlm` is a model for a plugin's tests: it plays the answers and tool calls it is given (`reply`, `callTools`), a call each, and records each request.

## Signing in

A login runs on the host, and what it asks of the person is its `SignIn`: one step at a time (`SignInStep`: a page to open, a code to enter, a key to paste, a question, or progress), numbered so an answer can only reach the step it was meant for. `Llm.signIns` lists the sign-ins running and each change, and `Llm.answerSignIn` answers the open step; clients reach them as `llm.sign-ins` and `llm.answer-sign-in`. A sign-in belongs to the host, not to the client that started it: a client that reloads, or another one, opens the stream and picks it up where it is, and an ended one stays listed a few seconds with how it ended (`SignInEnd`). The client starting a login says where its browser is and where the sign-in's page should offer to go back to (`LoginOptions`).

A provider of `Llm` keeps its sign-ins with `makeSignIns` (`signin.ts`): it runs each login flow, hands it `show` and `ask` for its steps, and serves `signIns` and `answerSignIn` from them, as `llm.pi-ai` does. `ProviderInfo` says who a provider is signed in as (`account`, `plan`), whether a sign-in uses the person's plan (`subscription`, `usesPlan`), and whether it stopped working (`expired`).

## Extending it

What the contract offers in each of the [five shapes](../../docs/plugins.md#the-five-shapes):

| Shape     | What the contract offers                                                                                                                                                                                                                                                                                                                                                                                            |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Add       | `Providers`: a provider (an endpoint speaking a protocol the llm plugin knows, and its models). In the web app, the Providers page's parts                                                                                                                                                                                                                                                                          |
| Intercept | `LlmRequestHook`: a model call and its stream, as its caller logged the request (time it, gate it, answer it, or wrap its stream; changing the request is `AgentRequestHook`'s, in [agent](../agent/README.md))(`ProviderLogoPart` and `ProviderRowPart` take over how a provider shows; `ModelPickerPart` and `ThinkingPickerPart`, how a setting's model and reasoning are chosen)                                |
| Observe   | `ModelsChanged`: what `providers` and `models` list changed                                                                                                                                                                                                                                                                                                                                                         |
| Call      | `Llm`: stream, models, classifiers (`classify`; codemode scripts call it as `models.classify`), image models (`generateImages`; scripts call it as `models.generateImages`), providers, logins and their sign-ins (`signIns`, `answerSignIn`); `SmallModel`: what a small task (a title) runs on (`chooseSmallModel`; `smallModel`, a provider's small model); clients call `LlmChannels`; in the web app, `Models` |
| Serve     | `Llm`, with `serveLlm` and `makeSignIns`: a plugin providing it replaces `llm.pi-ai`; `SmallModel`: one providing it replaces `llm.small-model`                                                                                                                                                                                                                                                                     |
